## 摘要（300–500字）
介绍多文档检索中的漏召回、冲突来源与无依据生成问题；概述 LightRAG 基座、自适应风险检索、声明级证据验证；列出在真实验证集和测试集上测得的主要指标 `[待实验填写]`；避免使用“全球首创”“突破 SOTA”等未经验证措辞。

## 第1章 研究背景与问题定义
1. RAG 工作流与知识图谱检索。
2. 固定预算检索与多跳问题难度不匹配。
3. 有引用 ≠ 事实有支持、冲突证据对生成的影响。
4. 形式化问题：`q, corpus → retrieved evidence → answer → verifiable claims`。
5. 目标：提高真实证据支持率，降低错误接受风险，同时控制延迟成本。

## 第2章 相关工作及复用声明
LightRAG、GraphRAG、Self-RAG、Corrective RAG、Adaptive RAG、NLI 事实一致性、RAGBench、MultiHop-RAG；按工作点比较并指出尚未解决的问题。逐项披露开源模型、数据集和许可证。

## 第3章 系统架构及数据流
组件图；语料预处理；LightRAG 入库、索引和检索模式；证据路径保留、引用映射；生成与 JSON 声明；事实验证；拒答策略；错误和异常处理；安全边界（文档提示注入）。

## 第4章 原创算法设计（最重要）
4.1 问题复杂度先验和首轮覆盖度的定义。
4.2 动态检索预算决策函数、复杂度和可解释性。
4.3 声明分解、分窗 NLI 支持与矛盾分数。
4.4 冲突判断、双阈值校准、选择性拒答。
4.5 算法伪代码、实现参数和失败条件。
4.6 与已有 adaptive RAG 和 attribution work 的异同。

## 第5章 数据集与实验设计
5.1 RAGBench：指定子任务 config、train/validation/test、标签与数据预处理。
5.2 MultiHop-RAG：独立 corpus、官方数据无单独测试 split；团队固定问题索引划分与防数据泄露。
5.3 运行环境：CPU/GPU、显存、Python/LightRAG/Ollama 版本和 commit。
5.4 统一生成模型、随机种子、温度和缓存条件。
5.5 四组消融 + 多个固定预算基线，消融/控制变量说明。
5.6 指标：支持判断准确率/F1、EM、token F1、证据匹配召回代理、回答覆盖率、错误接受率、时延 P50/P95 与检索调用数。
