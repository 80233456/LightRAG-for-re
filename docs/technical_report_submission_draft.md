# 证据链可信问答系统：基于 LightRAG 的动态检索与声明级证据验证

**参赛技术报告初稿（2026年10月15日提交版）**

> 团队、学校、指导老师、报名赛项名称和真实测试结果请按实际情况填写。该文档不声称已获得国奖或取得尚未测试的性能提升。

## 摘要

检索增强生成（RAG）允许大语言模型利用外部知识语料作答，但固定检索预算难以同时适应单跳问句和复杂多文档问题；此外，有引用并不意味着答案中的所有主张都得到证据支持。针对这两个问题，设计 EvidenceChain-RAG 工程原型，在 HKUDS/LightRAG 开源检索 SDK 上实现两个独立可测的候选模块：风险感知的动态检索控制与声明级证据冲突验证。系统首先评估问题风险及首轮证据覆盖度，决定是否扩展混合检索；再提取答案中的声明，利用自然语言推断模型对其进行支持、反驳、冲突和不足识别，并根据判定选择保留答案或拒答。工程提供来源追踪、四组消融、RAGBench 支持性分类评测和 MultiHop-RAG 多文档问答评测。当前项目在本地完成12项单元测试与离线演示，真实 LightRAG+Ollama 的端到端性能仍有待通过实测验证。

**关键词：**检索增强生成、LightRAG、动态检索、证据链、自然语言推断、选择性拒答。

## 1. 问题定义与研究目标

给定问题 q、语料库 D，系统检索相关上下文 E⊆D，生成答案 a，提取答案声明 C(a)={c₁,…,cₙ}，并判定每个声明是否由 E 支持。主要研究问题：（1）固定检索量对问题复杂度的适配不足；（2）引用路径不等于事实蕴含；（3）冲突来源可能导致未经验证的错误回答。目标是优化答案支持质量、错误接受率和检索计算成本之间的平衡。

## 2. 系统架构

语料导入 → LightRAG 索引 → 初轮向量检索 → 自适应检索控制器 → 可选图谱与向量混合扩展 → 证据去重和出处记录 → 候选答案生成 → 论断分解 → NLI 逐条支持/冲突判定 → 接受或拒答 → 输出证据审计结果。

LightRAG 的图谱和混合检索能力、Ollama 与已有语言模型均属于第三方开源基础。本项目独立实现并评测检索调度策略和可信性判定策略，不把原生引用、图谱索引或开源预训练模型描述为原创成果。

## 3. 候选创新一：风险感知动态检索

先以 naive 模式执行低开销检索，最多返回4个文本块。对问题计算启发式复杂度风险 r(q)，并计算证据对问题词项的覆盖率 c(q,E₀)。默认当 r(q)≥0.43 或 c(q,E₀)<0.30 时，追加 mix 模式检索，再将检索结果按来源与内容去重，最多输出8条证据。记录检索模式、调用次数和来源，以评估结果质量与时间成本。

**研究边界：**目前风险分数采用固定规则，并非训练所得策略。需在固定相同模型与语料的条件下，比较 naive@8、mix@8 和动态策略的效率—质量曲线，才能确认算法价值。

## 4. 候选创新二：声明级证据核验

将候选答案拆分为声明，对每条声明 cᵢ 与证据窗口 eⱼ 计算自然语言推断蕴含分数和矛盾分数；对多窗口的支持分数和矛盾分数取最大值 Sᵢ、Cᵢ，并使用分别设置的阈值判断 supported、refuted、conflict、insufficient。所有声明均被判定为 supported 时接受回答，否则拒答，并保留候选答案和证据标签供复核。

**研究边界：**NLI softmax 数值不能自动视为校准概率；应只在验证集选择阈值，并在测试集冻结。声明提取的遗漏和多文档联合推理困难是当前方法的局限。

## 5. 数据集和实验方案

### 5.1 RAGBench 证据支持性实验

读取 `galileo-ai/ragbench` 中指定配置的 documents、response、overall_supported 字段。此处任务是**给定答案的证据支持性判定**，不是新生成答案的端到端正确率。使用 Precision、Recall、F1、Accuracy，并记录样本和数据集指纹。

### 5.2 MultiHop-RAG 多跳问答实验

读取 `yixuantt/MultiHopRAG` 的 corpus 和 MultiHopRAG 两个配置，使用完整 corpus 建立索引。官方仅提供 train 配置，项目通过固定种子的题号划分建立 dev/validation/test。记录答案 Exact Match、token F1、覆盖率、检索调用数、延迟和严格子串的证据事实匹配代理指标。不能将字符串匹配代理解释成语义相关性判断。

### 5.3 四组消融

| 版本 | 动态检索 | 证据核验 | 目的 |
|---|---|---|---|
| baseline | 关闭 | 关闭 | 统一参考条件 |
| adaptive | 开启 | 关闭 | 检验检索调度贡献 |
| verify | 关闭 | 开启 | 检验证据判定贡献 |
| full | 开启 | 开启 | 检验联合效果 |

每组固定语料、生成模型、Embedding、随机种子与运行条件。对运行时延区分热启动和冷启动，推荐报告 P50/P95，并保存逐题 JSON 原始记录；阈值不能基于测试集反复调整。

## 7. 工程实现和复现

语言：Python≥3.10，建议3.11。核心源码位于 `src/evidencechain`；`scripts` 包含真实数据评测、环境诊断和复现命令；`tests` 包含单元测试；`configs` 保存实验矩阵和冻结划分。源代码托管地址：https://github.com/zyyyz-a/LightRAG 。

离线验证：
```bash
python -m pip install -e '.[test]'
python -m pytest -q
python scripts/run_demo.py ask --backend demo --variant full
```

真实运行需安装 Ollama 并下载 qwen2.5:7b 与 bge-m3，安装 `.[real,nli,eval]`，执行 `python scripts/check_environment.py`，随后进行 LightRAG 真实文档入库和问答。原始性能数字仅应来源于上述真实模型系统。

## 8. 局限和研究展望

当前动态检索策略基于启发式阈值，需要进一步探索可学习的预算分配政策；NLI 的领域偏差、证据文本截断、跨文档多跳合取推断、未检出的遗漏声明都可能影响证据可信度。后续应建立人工核验的支持/冲突集、学习证据预算策略，并进行基于错误接受风险的阈值校准。

## 9. 结论

项目完成了可测试的自适应检索和声明级证据核验原型，并构建了可追踪的统一消融实验与开放数据集评测接口。当前可以支持工程实现与离线测试的结论，但无法证明真实指标改善。在获取真机运行记录后，再补充实验数值和系统实际效果结论。
